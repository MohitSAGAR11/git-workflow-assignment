STEP 1 - LOCAL REPOSITORY SETUP
-------------------------------
git init -b main
    Creates a new, empty Git repository in the current folder (a hidden .git
    directory) and names the first branch "main".

git status
    Shows the state of the working directory and staging area: which files are
    untracked, modified, or staged for the next commit.

STEP 2 - GIT WORKFLOW EXECUTION
-------------------------------
git add index.html about.html
    Stages the two HTML files, i.e. adds their current content to the staging
    area so they are included in the next commit.

git commit -m "Initial commit: add index.html and about.html"
    Records the staged changes as a new commit (a snapshot) in the history,
    with the given message. This is the initial state of the project.

git diff
    Shows line-by-line changes in the working directory that are not yet
    staged. Used to check the edit to index.html before committing it.

git add index.html
git commit -m "Update index.html with assignment description"
    Stages the modified index.html and records it as the second commit.

git branch feature
    Creates a new branch named "feature" pointing at the current commit,
    without switching to it.

git branch
    Lists all local branches; the current branch is marked with "*".

git checkout feature
    Switches the working directory to the "feature" branch so that new commits
    are recorded on that branch.

git add about.html
git commit -m "Add skills section to about.html (feature branch)"
    Stages and commits the change to about.html on the feature branch only.

git checkout main
    Switches back to the main branch (the feature-branch change is not yet
    visible here).

git merge --no-ff feature -m "Merge branch feature into main"
    Merges the feature branch into main. --no-ff forces a merge commit even
    when a fast-forward is possible, so the branch activity stays visible in
    the history.

git log --oneline --graph --all --decorate
    Shows the commit history in compact form, one line per commit, with an
    ASCII graph of branches and merges and labels for branch pointers.

git log --stat
    Shows the full commit history (hash, author, date, message) along with
    the files changed and number of lines added/removed in each commit.

STEP 3 - .gitignore IMPLEMENTATION
----------------------------------
(.gitignore file created containing the patterns "*.log" and "temp/")

git add .gitignore
git commit -m "Add .gitignore to ignore .log files and temp/ folder"
    Stages and commits the .gitignore file so the ignore rules are shared
    with everyone who clones the repository.

git status
    Run after creating debug.log and temp/scratch.txt: they do not appear as
    untracked files, proving that Git is ignoring them.

git check-ignore -v debug.log temp/scratch.txt
    Confirms that the given paths are ignored and prints which line of
    .gitignore matches each one.

STEP 4 - UNDO OPERATION
-----------------------
git add index.html
git commit -m "Add contact placeholder comment to index.html"
    Makes an additional commit that will then be undone.

git log --oneline -3
    Shows the last 3 commits to confirm the new commit is at the top.

git revert --no-edit HEAD
    Undoes the last commit by creating a NEW commit that applies the exact
    opposite changes. History is not rewritten, so it is safe for commits
    that are (or will be) pushed to GitHub. --no-edit accepts the default
    commit message.

git log --oneline -4
    Shows that the original commit and the "Revert ..." commit both exist,
    while the file content is back to its previous state.

(Alternative, not used: git reset --hard HEAD~1 also undoes the last commit,
 but it deletes the commit from history, which is unsafe once it is pushed.)

STEP 5 - GITHUB INTEGRATION
---------------------------
(Public repository "git-workflow-assignment" created on GitHub.)

git remote add origin https://github.com/MohitSAGAR11/git-workflow-assignment.git
    Links the local repository to the GitHub repository under the short name
    "origin".

git remote -v
    Lists the configured remotes and their fetch/push URLs to verify the
    connection.

git push -u origin main
    Uploads all commits on main to GitHub. -u sets origin/main as the
    upstream branch so later "git push"/"git pull" need no arguments.

git push origin feature
    Pushes the feature branch to GitHub too, so the branch exists remotely.

git log --oneline --graph --all --decorate
    Run again after pushing: origin/main and origin/feature now appear next
    to the local branches, showing the remote matches the local history.
